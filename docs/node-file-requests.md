# 节点通信与文件请求（设计提案）

目标是让文件所属一侧的用户能在 Chat 或「等你回答」收到申请，看清谁要对哪个文件做什么，并决定是否放行。目标 agent 可以查看申请和结果。以下是拟议行为。

## 以 oracle #446 和 macmini #3 为例

| 申请 | macmini 用户看到的卡片 | 点「允许一次」之后 |
| --- | --- | --- |
| 建立通信 | oracle 的 #446 希望与本机 #3 通信 | 建立可撤销的通信关系，双方可直接发普通消息 |
| 写入 | oracle #446 希望把 `report.md`（18 KiB）写入 #3 的 `upload_files/report.md`，仅新建 | 接收端为这一份内容开放一次写入，校验成功后原子发布文件 |
| 读取 | oracle #446 希望从 #3 读取 `results/report.md`，副本将交给 oracle #446 | macmini 核对文件身份并准备已批准的副本，交给指定请求方 |

通信关系只授予发消息的能力。读和写按文件、方向分别授权。申请写入已有文件时默认保留原件；若支持覆盖，应重新展示覆盖目标并单独批准。目录同步需要展示文件清单、方向及冲突，申请方增加文件或改变操作时重新申请。

## 谁能看到、谁能确认

- 已登记且选择可发现的节点只公布名称、稳定标识和是否可接收申请。申请方在可见目录中选对方，接收方从请求也能识别并回访申请方。尚未配对时不开放 transcript、终端、文件目录。
- 路由使用节点 ID 和归属该节点的 pane ID。卡片附带人可读的主机名和编号；`#3` 单独不足以跨服务器定位。发送身份由认证连接绑定，不能相信请求正文自报的 `from`。
- 同一申请同时出现在目标 Chat 和「等你回答」，共用一个请求 ID。用户可以「允许一次」或「拒绝」。目标 agent 通过只读事件或 MCP 查询看到申请和状态；无须把控制消息或确认按键注入 TUI。
- 接收端验证决定来自该节点已登记的用户浏览器会话。服务器代管多台主机时，必须先建立目标主机与审批用户的归属关系。持有发送凭证、普通 MCP token 或知道目标编号均不能代为批准。缺少归属时留在待处理状态，并提示需要绑定审批用户。

## 通知先行，数据后送

1. 发起方提交元数据、操作和幂等键。写申请包含文件名、大小、内容摘要和目标目录；读申请包含精确路径和接收节点。接收端持久化后才回「已送达，待确认」。目标离线时由已部署服务器暂存通知，发起方看到「等待送达」。
2. 接收端批准后签发一次性授权，绑定请求、双方身份、操作、文件及有效期。读文件以接收端批准的版本为准；文件发生变化时要求重新确认。浏览器关闭、通知已读、agent 回复“可以”均不改变授权。
3. 双方都具备直连端点时优先直传。已有 SSH 信任且获准使用受限传输通道时可以走 SCP。接收服务控制读出的副本或临时写入区，并在发布前核验授权。普通 SSH 账号已有的系统权限不由 TmuxWeb 管控；系统不会把整机密钥交给 agent。缺少可用直连和合适的 SSH 通道时，文件字节才走部署的 TmuxWeb relay。
4. 切换线路沿用同一请求 ID 和授权。超时先查询接收记录，续传或重试只产生一次交付。只有接收端确认字节数和 SHA-256 后才显示「已完成」。拒绝、撤销或过期会使所有尚未完成的线路停止；已经送出的副本无法追回。

### P2P 网络边界

节点间消息、文件直传及 SCP 只使用已配对节点的局域网 IP 或其 Tailscale 分配的 IP。登记和发送时都要核对节点身份及实际 IP；对端自报的 `lan` / `tailnet` 标签不能作为依据。每次连接、重连和换路都执行相同校验。公网 IP 不作为候选，不发布、不探测，也不接受跳转到公网地址。用于 P2P 的监听只绑定选定的内网或 Tailscale 接口，不开放公网监听、端口映射或公网隧道。

私网端点不可达时，可沿用同一授权走已部署的 TmuxWeb relay；界面将线路标为「服务器中转」。联邦控制台用于访问中转服务器的地址不能自动升级为 P2P 候选。验收覆盖公网地址被错标为局域网、缓存中的旧公网地址，以及私网线路中断后三种情况，检查对公网节点的 P2P 连接尝试次数均为零。

## 收件状态与冲突

发起方分别看到「等待送达」「对方已收到，待确认」「已允许，等待传输」「传输中」「已完成」。通知送达回执来自接收端持久化成功，不能用 relay 接受消息或 SSH 连接成功替代。拒绝、取消、过期和传输失败各有独立状态。两台设备同时处理同一申请时，接收端只接受首次有效决定，并把最终状态同步回两端。临时失败沿用原请求重试，不重复发铃铛。

## 对接现有实现

| 已有能力 | 对接位置 |
| --- | --- |
| 联邦节点目录与连接 | 单向配置和共享范围见 [联邦说明](federation.md)。扩展受限目录与通信邀请，向双方展示可达状态及已配对状态。 |
| Chat 和「等你回答」 | 复用通知入口。文件请求另行持久化，其生命周期独立于终端菜单探测。重启、换 Chat 和暂时离线都应保留未过期申请。 |
| 原生 MCP `send_file` 及文件凭证 | 现有窄凭证是预先授权的静默写入。切换为逐次审批时，发送动作先返回请求 ID；原生 MCP、即时发送脚本及重试都经过相同的决策记录。读取需单独开放申请能力。 |
| 服务端中转 | 复用托管主机和联邦传输。控制通知允许经过服务器，数据线路独立选择。收件方既没有直连端点也没有 SSH 通道时，仍能在其绑定的控制台收到通知。 |

## 验收顺序

先用两个隔离节点验证一读一写。接收方用户应在线收到卡片，离线后重新打开也能看到；批准前不读取文件正文、不写最终文件。拒绝后切换线路也必须失败。目标 agent 能查询申请但无法批准。然后分别强制直连、SCP 和 relay，验证接收摘要一致，并测试断线重试、双设备同时决定和批准后文件被替换。最后再将已选择新策略的生产关系迁移，记录原静默凭证的处置结果。
